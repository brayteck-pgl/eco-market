2. PROMPTS RECONSTRUIDOS COMO EJEMPLOS DE LA METODOLOGIA

Prompt 1 - Priming y recopilacion de contexto
Tecnica: priming y meta-prompting.

Actua como desarrollador frontend senior con experiencia en comercio electronico
y accesibilidad. Ayudame a construir un prototipo web llamado EcoMarket, un
marketplace colombiano que conecta productores locales con consumidores
interesados en productos sostenibles.

Antes de escribir codigo, revisa el objetivo y pregunta por la informacion que
falte sobre usuarios, propuesta de valor, identidad visual, contenido y
restricciones tecnicas. No inventes datos del negocio. La solucion debe usar
HTML, CSS y JavaScript vanilla; no uses frameworks.

Prompt 2 - Propuesta UX/UI de la landing
Tecnica: role prompting y solicitud de propuesta estructurada antes del codigo.

Actua como disenador UX/UI para EcoMarket. Propone una landing accesible y
responsive que presente la marca, categorias de productos, destacados, impacto
de la compra local, productores, suscripcion y pie de pagina.

Entrega el orden de secciones, el objetivo de cada una, una jerarquia visual,
paleta y tipografias sugeridas, llamadas a la accion y consideraciones de
accesibilidad y movil. Explica brevemente las decisiones; no generes codigo.

Prompt 3 - Landing en HTML y CSS separados
Tecnica: zero-shot con especificacion y restricciones.

Genera index.html semantico en espanol para la propuesta aprobada de EcoMarket.
Incluye header, navegacion, hero, categorias, productos destacados, impacto,
productores, formulario de suscripcion y footer. Usa enlaces internos validos,
alt descriptivos, labels asociados y HTML accesible. No incluyas CSS ni
JavaScript embebido.

En una solicitud separada, genera styles.css mobile-first para ese HTML. Define
variables CSS, usa Grid o Flexbox, agrega media queries, foco visible, estados
hover moderados y una preferencia de movimiento reducido. No uses frameworks.

Prompt 4 - Dashboard y tabla de inventario
Tecnica: role prompting y especificacion por componentes.

Actua como disenador de dashboards administrativos. Propone un dashboard de
EcoMarket coherente con la landing, responsive y hecho con HTML/CSS/JavaScript
vanilla. Debe incluir navegacion lateral con cuatro opciones, bienvenida,
acciones, tres KPI y una tabla de productos con codigo, producto, categoria,
precio COP, stock, productor y estado. Incluye badges para Disponible, Stock
bajo y Agotado, cinco filas de ejemplo y acciones Editar/Eliminar.

En movil, plantea una navegacion que pueda abrirse y cerrarse con un boton
accesible, y una tabla que se pueda desplazar horizontalmente.

5. BORRADOR DE RESPUESTAS PARA LAS PREGUNTAS DE REFLEXION

Estas respuestas deben revisarse y personalizarse con la experiencia del grupo.

1. Diferencias entre zero-shot, one-shot y few-shot:
   Zero-shot solicita una tarea sin ejemplos; one-shot aporta un ejemplo; few-shot
   aporta varios. En una generacion de productos, los ejemplos ayudan a mantener
   la forma y los tipos del JSON, pero el resultado debe validarse con reglas de
   JavaScript.

2. Importancia de definir estructura y reglas antes de generar datos:
   Permite que la IA conozca los nombres de campos, tipos, rangos y valores
   permitidos. Esto reduce registros incompatibles con el formulario y evita
   corregir inconsistencias de forma manual despues.

3. Errores detectados por la validacion:
   En la ejecucion sobre los 35 productos no se encontraron errores de datos.
   Al comparar el validador con las reglas del taller se detecto que faltaba
   verificar la longitud de nombre y productor; se agrego esa regla y se probaron
   valores dentro y fuera de los limites.

4. Ventajas de separar datos, logica y presentacion:
   productos.json contiene los datos, app.js implementa la interaccion y los
   calculos, y los HTML/CSS presentan la interfaz. Esta separacion facilita
   localizar errores y cambiar una parte sin rehacer las demas.

5. Limitaciones de localStorage frente a una base de datos:
   localStorage solo persiste en el navegador y origen actuales; no sincroniza
   entre usuarios o dispositivos, no ofrece respaldo centralizado ni control de
   acceso y puede ser borrado por el usuario.

6. Cambios para produccion:
   Se requeririan backend y base de datos compartida, autenticacion y permisos,
   validacion tambien en el servidor, respaldo y monitoreo, y un servicio real
   para suscripciones. Si se habilitan compras, tambien se integrarian inventario
   transaccional, logistica y un proveedor de pagos seguro.
